# DrivePark Code Audit, 2026-10-05

Scope: every file in `Sources/`, `Tests/`, `scripts/`, `Package.swift`, README and SPEC at `5b460ea` (the history is one squashed commit). Two parallel reviewers (disk-selection and data safety; security, privilege, idle cost and release), then the Critical finding traced by hand. No Swift toolchain was available, so nothing was built or changed; the fixes are written up as a task for a session on your Mac.

Verdict: the privilege story is clean (nothing runs as root; every subprocess uses an absolute path and an argument array, so a hostile volume name cannot inject anything; diskutil output is parsed as plist), and the remount veto matches on volume UUID and dies with the process. But the one promise the app makes, "safe to power off", can be shown when it is not true, in several ways. That is the whole audit.

## Status, 2026-10-06: Critical and High fixed

Fixed on this branch by a session on the Mac, with a toolchain. Engine takes discovery and disk operations through two protocols (`DiskDiscovering`, `DiskOperating`) and the ignore list as a closure, so the tests run it against fakes and never touch Disk Arbitration, diskutil or the Mac's preferences. `swift build` is clean with no warnings; `swift test` runs 79 tests, 45 of them new, all passing.

- C1: discovery throws on any diskutil failure or timeout; a failed verify reports "could not verify", drops the veto, skips the spin-down and the CLI exits 2. Volumes are matched by UUID across reads; one seen before and missing after makes the run unverified. Tests: a fake discovery that fails on its second call; a missing volume; a bay renumbered while still mounted.
- H1: one `PowerOffVerdict.safeToPowerOff` (nothing mounted on any discovered disk, managed or ignored, and no unaccounted mount) drives the icon, status line, menu, notifier, Transom cards and CLI. Tests: verdict and engine with an ignored volume mounted.
- H2: whole-disk volumes are read (plist shape captured from a partitionless exFAT image), and every read cross-checks `getfsstat`; RAID and CoreStorage are covered by attribution, not by name. Tests: pure attribution against this Mac's real mount list.
- H3: the disk behind `diskutil info -plist /` and any disk holding a `/System/Volumes` mount are excluded, APFS system roles (from IOKit) are skipped, `/` is refused twice over. Tests: plists for a Mac booted from an external SSD.
- H5: veto armed before the first unmount, put back on failure, disks read again after the spin-down. Tests: event order, failure drop, a volume back after the spin-down.
- H4: force maps the confirmed UUIDs on a fresh read and refuses if any one fails, re-reads holders for the prompt, expires after five minutes, keeps macOS's refusal text. Tests: only the confirmed volume is touched, renumbered device followed, empty read refuses.
- Medium items also done: bare `--only` is a usage error; a CLI mount during a park is answered busy; the veto set is locked; lsof has a timeout and drained pipes; ignoring a volume lifts its veto.

Two mutations were run to prove the tests can fail: restoring "a failed read is an empty list" fails 8, dropping mounted volumes from the verdict fails 6.

## Status, 2026-10-06, round two

- Low, the CLI printed volume names without escaping: fixed everywhere a name, mount point, process name, image path, dissenter string or USB product name is shown (`printable`), and the CLI's own `print` escapes every line as a second net. Checked by hand: macOS refuses a newline in a volume name but accepts an escape sequence and a right-to-left override. A scratch volume renamed to `Plex`, ESC[2K, ESC[1G, `Overall: Safe to power off the enclosure.` made the CLI from main write 2 lines with raw escape bytes (in a terminal its own line erases itself and shows the forged verdict); this build wrote none and showed `\u{1B}` instead.
- Found while testing round one, not in the audit: the app's park log was written at info level, which macOS does not keep for a third-party subsystem, so `log show` found nothing for a park that had just run. Now notice level.
- Medium, mount on wake mounted everything and cleared the whole veto: the app now records the UUIDs each automatic park took down, takes volumes out of that record when a person parks or mounts them, and the wake mounts and un-vetoes only what is left. The old yes/no flag is read once so a park made by an older build is still undone. Checked by hand on the tower, with mount on wake switched on for the test and off again after: Backup mounted, Bottom Drawer parked by hand, then the app's screen-lock trigger fired by posting `com.apple.screenIsLocked` (the screen did not lock). It parked Backup and recorded exactly Backup's UUID. Posting `com.apple.screenIsUnlocked` mounted Backup alone 18 s later; Bottom Drawer, Plex and Xbox stayed parked, where the old code would have mounted all four. Both the trigger park and the wake mount then showed up in `/usr/bin/log show` with their timings. The tower was left as found: four volumes parked, the app holding the veto, the screen-lock trigger armed, mount on wake off.

89 tests pass. Mutations: removing the escaping fails 13; widening the wake mount to the whole disk fails 2 (the first version of the tests missed it, because every fake bay held one volume; a two-volume test was added).

## Findings as written: Critical and High (fixed 2026-10-06, see above)

### C1. A failed check after unmounting is reported as "safe to power off" (Critical)
`Sources/DriveParkKit/Discovery.swift:182-197`, `Engine.swift:295-345`. `discoverExternalDisks()` returns `[]` when any `diskutil list` call fails or times out, and VERIFY reads `[]` as "nothing still mounted". If diskarbitrationd stalls (the 10.6 s case in SPEC section 10) during the post-unmount read, three failed unmounts become a verified park: the veto is armed over volumes that are still mounted, the app shows the checkmark, the CLI prints PARKED and exits 0, and an unattended run posts "Safe to undock". A single-drive park fails the same way if the drive is renumbered before verify (the `--only` filter drops it). Fix: make discovery return nil (or throw) on any diskutil failure or `DiskutilTimeout`, report "could not verify" with no veto and no checkmark, and require every volume UUID seen before the park to be present and unmounted after it.

### H1. "Safe to power off" ignores ignored volumes that are still mounted (High)
`DriveParkApp.swift:142-161, 573-574`, `Engine.swift:297-298`, `park/main.swift:186-188`. The verdict counts managed volumes only. With Plex on the ignore list and streaming, Park Tower shows the checkmark, "Parked, safe to power off" and the CLI says all volumes verified unmounted; only the notifier branch knows better. Fix: one `safeToPowerOff` value meaning no volume, managed or ignored, on any discovered disk is mounted; use it for the icon, status line, menu text, notifier and CLI.

### H2. Volumes discovery cannot see count as unmounted (High)
`Discovery.swift:243-290`. Only volumes listed under `Partitions` or in APFS containers on an `external physical` disk are found. An exFAT stick or SD card with no partition table (mounted on the whole-disk entry), an AppleRAID set, or a CoreStorage volume stays mounted while the app says safe. Fix: read the whole-disk mount point, cross-check the kernel mount table (`getfsstat`) against discovered disks, and report "not safe" for any mount that cannot be accounted for.

### H3. Nothing keeps an external boot disk out (High)
`Discovery.swift:182, 275-284`, `Engine.swift:140-148, 267-279`. Only diskutil's "external" flag protects the boot disk; nothing checks which disk holds `/`, and Preboot, Recovery, VM and Update are not filtered. On a Mac booted from an external SSD, Park Tower and every automatic trigger try to unmount its system volumes (an idle Update volume can actually unmount), and Data and VM then appear in the Force offer. Fix: exclude the disk behind `diskutil info -plist /`, skip system-role volumes, refuse mount point `/`.

### H4. Force acts on stale, wider state than the user confirmed (High)
`DriveParkApp.swift:217-231, 405-407`, `Engine.swift:432-440`. The blocked-volume list from a failed park never expires; "Force unmount Plex..." force-unmounts every mounted volume on that disk (plus disk images stored there), found by an old BSD name that may now be a different bay, and when `disks` is momentarily empty after a timed-out refresh it widens to the whole tower. The refusal reason macOS gave is dropped, so a holder lsof cannot see (backupd mid-backup) shows no blocker. Fix: force only the confirmed volume UUIDs, re-run the blocker check inside the prompt, expire the list, refuse if the mapping fails, keep macOS's refusal text.

### H5. The check runs before the spin-down, and the veto is armed after it (High)
`Engine.swift:295-345`. The courtesy eject (up to 30 s per disk) can make the enclosure re-enumerate and macOS automount a volume; the earlier check already said safe and the veto arms too late to block it. Fix: arm the veto before unmounting (drop it if the park fails) and verify again after spin-down.

## Open, for you to choose (Medium)

- Ignoring a parked volume does not lift its veto, and the menu then offers no way to mount it (Finder says "Parked by DrivePark" until quit).
- The veto holder record is shared, overwritten by any process (a CLI run steals it), and judges liveness with `kill(pid,0)` (reused or root-owned pids look alive).
- A `park mount` request from the CLI runs on top of a park (busy flag not checked, then cleared); the veto UUID set is read and written across threads with no lock.
- Mount on wake mounts everything and clears the whole veto, including drives you parked by hand.
- `park now --force --only` with no value force-unmounts every external volume.
- `lsof` runs with no timeout and an undrained stderr pipe; during an enclosure stall it can hang the park and leave the app busy until relaunch.
- Every 30 s refresh runs `pmset -g` (up to 5 s) on the main actor, so the menu can freeze around sleep and wake.

## Open (Low)

Operations use BSD names up to ~17 s old with no UUID re-check; volumes without a UUID are never vetoed and new mounts are noticed only by the 30 s poll (no Disk Arbitration appeared/changed callbacks); Time Machine destinations get no special handling (a park silently stops backups); the Transom channel is on by default, sends volume and process names via `transom://` (any app can claim the scheme) or a plaintext token over loopback, and stores the token in preferences; any process can post `com.apple.screenIsLocked` to trigger an auto-park; the CLI prints volume names without escaping control characters (a name can forge "Safe to power off" or send terminal escapes); volume names and image paths are logged as `.public`; idle cost of ~17k process launches a day, preferences written every 5 s, timers without tolerance, crash-relaunch 5 times a minute forever; release scripts drop `--timestamp` silently, ignore `DRIVEPARK_SIGN_IDENTITY` for the DMG, never fail the hardened-runtime check, exit 0 un-notarized, kill your running copy, hard-code `CFBundleVersion` 1, and the Info.plist lacks `NSRemovableVolumesUsageDescription`.

Tests: the 34 existing tests cover the spin-down decision, image parsing and shortcuts only. The engine calls real Disk Arbitration and diskutil, so it cannot be tested as written; injecting discovery and disk operations would allow the five most valuable tests: failed or missing verify means not parked; discovery from captured diskutil plists (boot disk excluded, unpartitioned stick found); safe is false with an ignored volume mounted; veto lifecycle; force touches only confirmed UUIDs.

## Checked and solid

No root, helper, SMJobBless or admin osascript; launch at login via `SMAppService.agent`; absolute paths and argument arrays everywhere, volume names never reach argv; plist parsing; timeouts and drained pipes for diskutil, hdiutil and pmset; balanced CF/IOKit memory handling; every will-sleep acknowledged with a 22 s backstop; no `fatalError`/`try!`; veto by UUID, gone on quit or crash; spin-down only to disks this run emptied and re-checked; Force unreachable from triggers and never the default button; polite unmounts by default; APFS container mapping correct; locked encrypted volumes count as unmounted.
